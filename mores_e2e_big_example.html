MoReS E2E 大例子讲义

只讲 MoReS，一条完整主线：原始样本 → tokenize → tokenized_dataset → batch → forward → hook → loss → backward。

1. 总体路线

┌── 先把整条 MoReS 主线看清楚 ─────────────────────────────────────────────────┐ │ │ │ raw adapter[i] = CanonicalSample │ │ │ │ │ ▼ │ │ preprocessor.tokenize(sample, processor, model.config, ...) │ │ │ │ │ ├─ build_messages(...) │ │ ├─ full_text = apply_chat_template(messages, add_generation_prompt=False)│ │ ├─ prompt_text = apply_chat_template(prompt_messages, add_generation_prompt=True) │ ├─ processor(text=full_text, images=...) -> input_ids │ │ ├─ processor(text=prompt_text, images=...) -> prompt_len │ │ ├─ labels[:prompt_len] = IGNORE_INDEX │ │ └─ build_mores_intervention_mask(model.config, input_ids) │ │ -> intervention_mask [S] │ │ │ │ tokenized_dataset[i] = 单条训练张量字典 │ │ │ │ │ ▼ │ │ preprocessor.collate([sample0, sample1, ...]) │ │ │ │ │ └─ batch = {input_ids[B,S], labels[B,S], attention_mask[B,S], │ │ intervention_mask[B,S], ...} │ │ │ │ trainer: │ │ batch = to_device(batch, device) │ │ forward_batch = method_obj.build_forward_batch(batch) │ │ outputs = model(**forward_batch) │ │ │ │ model(**forward_batch): │ │ 1. pre-hook 先读 intervention_mask │ │ 2. Qwen 内部 input_ids -> embed_tokens(input_ids) -> hidden_states [B,S,D]│ │ 3. 每层 decoder forward 后触发 layer_hook(adapter) │ │ 4. 只改 output[intervention_mask] 这些 token │ │ │ │ 最后: loss.backward() + optimizer.step() │ │ 只更新 model.mores_adapters │ └────────────────────────────────────────────────────────────────────────────────┘

2. 先把单层 Transformer 画清楚

这是当前 Qwen decoder layer 的结构。MoReS 不改里面的 q_proj / v_proj / mlp 子模块，而是等整层输出出来以后再动它。

┌── Qwen2_5_VLDecoderLayer(hidden_size=D, intermediate_size=M) ────────────────┐ │ │ │ __init__: │ │ ┌───────────────────────────────────────────────────────────────────────┐ │ │ │ input_layernorm = Qwen2RMSNorm(D) │ │ │ │ self_attn = Qwen2_5_VLAttention(D) │ │ │ │ │ q_proj = Linear(D→D, no bias) │ │ │ │ │ k_proj = Linear(D→D, no bias) │ │ │ │ │ v_proj = Linear(D→D, no bias) │ │ │ │ │ o_proj = Linear(D→D, no bias) │ │ │ │ post_attention_layernorm = Qwen2RMSNorm(D) │ │ │ │ mlp = Qwen2MLP(D, M) │ │ │ │ │ gate_proj = Linear(D→M, no bias) │ │ │ │ │ up_proj = Linear(D→M, no bias) │ │ │ │ │ down_proj = Linear(M→D, no bias) │ │ │ └───────────────────────────────────────────────────────────────────────┘ │ │ │ │ forward: │ │ │ │ hidden_states x (B, S, D) │ │ │ │ │ ┌────┤ │ │ │ ▼ │ │ │ input_layernorm │ │ │ │ │ │ │ ▼ │ │ │ self_attn │ │ │ │ │ │ └──► + ◄────── residual 1 │ │ │ │ │ ┌────┤ │ │ │ ▼ │ │ │ post_attention_layernorm │ │ │ │ │ │ │ ▼ │ │ │ mlp │ │ │ │ │ │ └──► + ◄────── residual 2 │ │ │ │ │ ▼ │ │ output hidden_states (B, S, D) │ └───────────────────────────────────────────────────────────────────────────────┘

3. MoReS hook 到底插在哪

┌── 单层输出后，MoReS hook 插入点 ───────────────────────────────────────────────┐ │ │ │ layer.forward(...) │ │ └─ output = residual_2 + mlp_out -> (B, S, D) │ │ │ │ │ ▼ │ │ register_forward_hook(layer_hook(adapter)) │ │ │ │ │ ▼ │ │ intervention_mask = current_intervention_mask.to(output.device) │ │ updated = output.clone() │ │ updated[intervention_mask] = adapter(output[intervention_mask]) │ │ return updated │ │ │ │ 所以 MoReS 注入点是: 整层 output hidden_states 出来之后 │ │ 不是 attention 内部，也不是 mlp 内部。 │ └────────────────────────────────────────────────────────────────────────────────┘
┌── 两层串起来看：同一份 intervention_mask 如何在每层复用 ──────────────────────┐ │ │ │ current_intervention_mask = [T,T,T,T,F,F,F,T,T,T,T,T,F,...] │ │ │ │ hidden_states_0 (B,S,D) │ │ │ │ │ ▼ │ │ Layer 0 forward -> output_0 │ │ │ │ │ ▼ │ │ hook 0: updated_0[current_intervention_mask] = adapter_0(...) │ │ │ │ │ ▼ │ │ hidden_states_1 = updated_0 │ │ │ │ │ ▼ │ │ Layer 1 forward -> output_1 │ │ │ │ │ ▼ │ │ hook 1: updated_1[current_intervention_mask] = adapter_1(...) │ │ │ │ 结论：同一份 mask 在每层重复用，但每层有自己独立的 adapter。 │ └────────────────────────────────────────────────────────────────────────────────┘

8. 正式开始训练前，prepare_model_impl 做了什么

prepare_model_impl(model, processor, config) 1. self.image_token_id = int(model.config.image_token_id) 2. 冻结整个 Qwen: for param in model.parameters(): param.requires_grad = False 3. hidden_size = int(model.config.text_config.hidden_size) 4. layers = list(model.model.language_model.layers) 5. 对每一层: adapter = MoReSAdapter(hidden_size, rank=1) layer.register_forward_hook(self.layer_hook(adapter)) 6. model.mores_adapters = nn.ModuleList(adapters) 7. model.register_forward_pre_hook(self.forward_pre_hook, with_kwargs=True)
这一步之后模型变成什么状态
原始 Qwen
+
1 个 model-level pre-hook
+
N 个 layer hooks
+
N 个 MoReSAdapters
→
MoReS-ready model
┌── 训练主线大图：从 prepare_model_impl() 到 hook 真正传导 ───────────────────────┐ │ │ │ Stage A. 训练开始前，先改模型结构 │ │ │ │ trainer.py │ │ method_obj = MoReSMethod() │ │ self.model, info_str = method_obj.prepare_model(...) │ │ │ │ prepare_model_impl(...) 做的事: │ │ 1. 冻结整个 Qwen backbone │ │ 2. layers = list(model.model.language_model.layers) │ │ 3. 对每层创建一个 MoReSAdapter │ │ 4. 对每层注册 layer.register_forward_hook(hook_fn) │ │ 5. 对整个 model 注册 forward_pre_hook │ │ 6. model.mores_adapters = nn.ModuleList(adapters) │ │ │ │ 这一刻还没有跑 forward。只是把“等会儿要自动触发的钩子”先挂到模型上。 │ │ │ │ Stage B. 构造 optimizer │ │ │ │ trainer.py │ │ param_groups = method_obj.get_trainable_params(self.model) │ │ optimizer = AdamW(param_groups, ...) │ │ │ │ get_trainable_params(...) 只返回 model.mores_adapters.parameters() │ │ 所以之后就算 backward 了，能被 optimizer.step() 更新的也只有 adapters。 │ │ │ │ Stage C. 进入一个真正的训练 step │ │ │ │ batch from collate = { │ │ input_ids[B,S], labels[B,S], attention_mask[B,S], │ │ intervention_mask[B,S], pixel_values, image_grid_thw │ │ } │ │ │ │ │ ▼ │ │ forward_batch = build_forward_batch(batch) │ │ │ │ │ ▼ │ │ outputs = self.model(**forward_batch) │ │ │ │ Stage D. forward 一开始先触发 pre-hook │ │ │ │ 因为 model 上已经挂了: │ │ register_forward_pre_hook(self.forward_pre_hook, with_kwargs=True) │ │ │ │ 所以 self.model(**forward_batch) 一开始先跑: │ │ input_ids = kwargs["input_ids"] │ │ intervention_mask = kwargs["intervention_mask"] │ │ self.current_intervention_mask = intervention_mask │ │ │ │ 这一步不改 hidden states，只是把“这次要改哪些 token”缓存下来。 │ │ │ │ Stage E. Qwen 正常 forward │ │ │ │ input_ids[B,S] │ │ │ │ │ ▼ │ │ embed_tokens(input_ids) -> inputs_embeds[B,S,D] │ │ │ │ │ ▼ │ │ Layer 0 forward -> raw_output_0[B,S,D] │ │ │ │ │ ▼ │ │ hook 0 自动触发: │ │ updated_0 = raw_output_0.clone() │ │ updated_0[mask] = adapter_0(raw_output_0[mask]) │ │ return updated_0 │ │ │ │ │ ▼ │ │ Layer 1 forward -> raw_output_1[B,S,D] │ │ │ │ │ ▼ │ │ hook 1 自动触发 │ │ ... │ │ │ │ 所以“传导”其实是: │ │ pre-hook 先缓存 mask │ │ 然后每层 layer hook 都读取同一份 mask │ │ 再把当前层 output 的少量 token 改掉，传给下一层 │ │ │ │ Stage F. forward 结束后 │ │ │ │ outputs -> compute_loss(...) -> loss.backward() -> optimizer.step() │ │ │ │ 因为 backbone 已冻结，optimizer 又只拿 adapters， │ │ 所以最后更新的只有每层的 MoReSAdapter。 │ └────────────────────────────────────────────────────────────────────────────────┘
把上面这张训练主线图，直接套到当前两个样本的 batch 上
当前 batch 还是前面那两个样本:

batch["input_ids"].shape = [2, 21]
batch["intervention_mask"].shape = [2, 21]

batch["intervention_mask"] =
[
  [T,T,T,T,F,F,F,T,T,T,T,T,F,F,F,F,F,F,F,F,F],
  [T,T,T,T,T,T,T,T,F,F,F,F,F,F,F,F,F,F,F,F,F]
]

所以这次 forward 一开始，pre-hook 缓存的就是这张表。

然后进入 Layer 0:
  raw_output_0.shape = [2, 21, D]

  sample0 这行选中了 9 个位置:
    0,1,2,3,7,8,9,10,11

  sample1 这行选中了 8 个位置:
    0,1,2,3,4,5,6,7

  所以:
    raw_output_0[intervention_mask].shape = [17, D]

  hook 0 做:
    updated_0 = raw_output_0.clone()
    updated_0[intervention_mask] = adapter_0(raw_output_0[intervention_mask])

  这一步结束后:
    只有 17 个 visual token hidden states 被改
    其余 token 完全不动

然后 updated_0 进入 Layer 1:
  raw_output_1.shape = [2, 21, D]

  hook 1 又读同一份 current_intervention_mask
  再次只改那 17 个位置

一直到最后一层都一样。

所以“hook 传导”最短就是:
  pre-hook 把 mask 存起来
  layer 0 hook 读它 -> 改少量 token
  layer 1 hook 读它 -> 改同一批位置
  ...
  最后一层 hook 读它 -> 改同一批位置

然后 loss.backward() 之后:
  Qwen backbone 不更新
  只有 adapter_0, adapter_1, ... adapter_N 的参数更新
optimizer 为什么最后只会更新 adapters
trainer.py:
  self.model, info_str = method_obj.prepare_model(...)
  param_groups = method_obj.get_trainable_params(self.model)
  optimizer = AdamW(param_groups, ...)

mores.py:
  def get_trainable_params(self, model):
      adapters = getattr(model, "mores_adapters", None)
      params = [param for param in adapters.parameters() if param.requires_grad]
      return [{"params": params}]

9. forward 真正发生什么：前面的 batch 字段怎么接上模型

9.1 trainer 先把 batch 变成 forward_batch
trainer.py:
  batch = to_device(batch, device)
  batch["labels"] = method_obj.preprocess_labels(...)
  forward_batch = method_obj.build_forward_batch(batch)

对 MoReS:
  preprocess_labels(...) 不改 labels
  build_forward_batch(...) 只会丢掉 instruction_supervision_mask

所以:
  forward_batch = {
    "input_ids": batch["input_ids"],
    "labels": batch["labels"],
    "attention_mask": batch["attention_mask"],
    "intervention_mask": batch["intervention_mask"],
    "pixel_values": batch["pixel_values"],
    "image_grid_thw": batch["image_grid_thw"],
  }
9.2 self.model(**forward_batch) 这句到底等价于什么
trainer.py:
  outputs = self.model(**forward_batch)

等价于:
  self.model(
    input_ids=...,
    labels=...,
    attention_mask=...,
    intervention_mask=...,
    pixel_values=...,
    image_grid_thw=...,
  )

其中:
  input_ids / labels / attention_mask / pixel_values / image_grid_thw
    是 Qwen 顶层 forward 原生认识的正式参数

  intervention_mask
    不是 Qwen 原生参数
    它通过 **kwargs 进来，是给 MoReS pre-hook 读的
┌── 图 1: batch 里的字段是怎么接上 self.model(**forward_batch) 的 ─────────────────┐ │ │ │ trainer 里手上先有: │ │ │ │ batch = { │ │ "input_ids": batch["input_ids"], # [B,S] │ │ "labels": batch["labels"], # [B,S] │ │ "attention_mask": batch["attention_mask"], # [B,S] │ │ "intervention_mask": batch["intervention_mask"], # [B,S] │ │ "pixel_values": batch["pixel_values"], │ │ "image_grid_thw": batch["image_grid_thw"], │ │ "instruction_supervision_mask": ... # 只有 L2T 才有，MoReS 这里没有 │ │ } │ │ │ │ build_forward_batch(batch) 之后: │ │ │ │ forward_batch = { │ │ "input_ids": ..., │ │ "labels": ..., │ │ "attention_mask": ..., │ │ "intervention_mask": ..., │ │ "pixel_values": ..., │ │ "image_grid_thw": ..., │ │ } │ │ │ │ 然后 trainer 调: │ │ │ │ outputs = self.model(**forward_batch) │ │ │ │ Python 会先做关键字展开，相当于: │ │ │ │ self.model( │ │ input_ids=forward_batch["input_ids"], │ │ labels=forward_batch["labels"], │ │ attention_mask=forward_batch["attention_mask"], │ │ intervention_mask=forward_batch["intervention_mask"], │ │ pixel_values=forward_batch["pixel_values"], │ │ image_grid_thw=forward_batch["image_grid_thw"], │ │ ) │ │ │ │ Qwen 顶层 forward(...) 原生认识: │ │ input_ids / labels / attention_mask / pixel_values / image_grid_thw │ │ │ │ intervention_mask 不在 Qwen 那组显式参数里，所以会落到 **kwargs │ │ │ │ 也就是说，这次调用开始时，真实 kwargs 大概就是: │ │ │ │ kwargs = { │ │ "input_ids": tensor([B,S]), │ │ "labels": tensor([B,S]), │ │ "attention_mask": tensor([B,S]), │ │ "intervention_mask": tensor([B,S]), │ │ "pixel_values": ..., │ │ "image_grid_thw": ..., │ │ } │ │ │ │ 这就是为什么 forward_pre_hook(...) 里可以直接写: │ │ input_ids = kwargs["input_ids"] │ │ intervention_mask = kwargs["intervention_mask"] │ └────────────────────────────────────────────────────────────────────────────────┘
9.2.1 这里真正发生的顺序
1. trainer 先构造 forward_batch
2. Python 先把 **forward_batch 展开成一组命名参数
3. 因为 model 上挂了 register_forward_pre_hook(..., with_kwargs=True)
   所以 Qwen forward 正式执行前，pre-hook 先拿到同一份 kwargs
4. pre-hook 从 kwargs 里读 intervention_mask，缓存成 self.current_intervention_mask
5. 然后 Qwen forward 才继续往下执行
9.3 pre-hook 先读 intervention_mask
因为 prepare_model_impl(...) 里挂了:
  model.register_forward_pre_hook(self.forward_pre_hook, with_kwargs=True)

所以这次 forward 一开始先跑:

input_ids = kwargs["input_ids"]
intervention_mask = kwargs["intervention_mask"].to(
    device=input_ids.device,
    dtype=torch.bool,
)

if intervention_mask.shape != input_ids.shape[:2]:
    raise ValueError(...)

self.current_intervention_mask = intervention_mask

对当前这个 batch:
  input_ids.shape = [2, 21]
  intervention_mask.shape = [2, 21]

所以:
  current_intervention_mask =
  [
    [T,T,T,T,F,F,F,T,T,T,T,T,F,F,F,F,F,F,F,F,F],
    [T,T,T,T,T,T,T,T,F,F,F,F,F,F,F,F,F,F,F,F,F]
  ]
9.4 Qwen 内部什么时候把 input_ids 变成 embedding
Qwen 内部 language model forward 里:

if inputs_embeds is None:
    inputs_embeds = self.embed_tokens(input_ids)

hidden_states = inputs_embeds

所以:
  input_ids.shape     = [B, S]
  inputs_embeds.shape = [B, S, D]
  hidden_states.shape = [B, S, D]

关键点:
  token 的位置维 [B,S] 没变
  只是每个位置的内容从 token id 变成向量
9.5 每层输出后，layer_hook 怎么只改少量 visual token
假设某一层输出:
  output.shape = [2, 21, D]

而:
  current_intervention_mask =
  [
    [T,T,T,T,F,F,F,T,T,T,T,T,F,F,F,F,F,F,F,F,F],
    [T,T,T,T,T,T,T,T,F,F,F,F,F,F,F,F,F,F,F,F,F]
  ]

所以:
  sample0 被选中的位置 = 9 个
    0,1,2,3,7,8,9,10,11

  sample1 被选中的位置 = 8 个
    0,1,2,3,4,5,6,7

因此:
  output[intervention_mask].shape = [17, D]

hook 里做:
  updated = output.clone()
  updated[intervention_mask] = adapter(output[intervention_mask])

结果:
  这个 batch 里只有 17 个 visual token hidden states 被改
  所有 text token 都不改
┌── 图 2: register_forward_hook(...) 到底是怎么工作的 ─────────────────────────┐ │ │ │ prepare_model_impl(...) 里做的不是“立刻改输出”，而是先注册回调: │ │ │ │ for layer in layers: │ │ adapter = MoReSAdapter(hidden_size, 1) │ │ hook_fn = self.layer_hook(adapter) │ │ layer.register_forward_hook(hook_fn) │ │ │ │ 所以 prepare 阶段结束后，每一层身上都挂着一个“等会儿 forward 完再调用”的函数。 │ │ │ │ 运行时某一层真正执行时，顺序是: │ │ │ │ hidden_states_in │ │ │ │ │ ▼ │ │ layer.forward(hidden_states_in) │ │ │ │ │ ▼ │ │ raw_output = output of this layer # shape [B,S,D] │ │ │ │ │ ▼ │ │ PyTorch 自动调用 hook_fn(layer, args, raw_output) │ │ │ │ │ ▼ │ │ hook_fn 内部: │ │ intervention_mask = self.current_intervention_mask │ │ updated = raw_output.clone() │ │ updated[intervention_mask] = adapter(raw_output[intervention_mask]) │ │ return updated │ │ │ │ │ ▼ │ │ layer 最终对外返回的不是 raw_output，而是 updated │ │ │ │ │ ▼ │ │ 下一层收到的是 updated │ │ │ │ 重点: register_forward_hook(...) 本身只是在 module 上“登记一个回调”。 │ │ 真正调用它的是 PyTorch，在该层 forward 已经算完之后自动触发。 │ └────────────────────────────────────────────────────────────────────────────────┘
9.5.1 外层 layer_hook(adapter) 和内层 hook(...) 的关系
mores.py 里写的是:

def layer_hook(self, adapter):
    def hook(module, args, output):
        intervention_mask = self.current_intervention_mask.to(output.device)
        updated = output.clone()
        updated[intervention_mask] = adapter(output[intervention_mask])
        return updated
    return hook

所以:
  self.layer_hook(adapter)
不是“直接执行修改”，而是先返回一个真正给 PyTorch 用的 hook 函数。

也就是:
  hook_fn = self.layer_hook(adapter)
  layer.register_forward_hook(hook_fn)

真正到运行时被 PyTorch 调用的是里面那个:
  hook(module, args, output)

10. 一个训练 step 到结束，最后更新了谁

1. batch = to_device(batch, device) 2. batch["labels"] = method_obj.preprocess_labels(...) # MoReS 这里不改 3. forward_batch = method_obj.build_forward_batch(batch) 4. outputs = self.model(**forward_batch) ├─ pre-hook 先缓存 current_intervention_mask ├─ Qwen 内部 input_ids -> inputs_embeds -> hidden_states └─ 每层 layer_hook 只改 output[intervention_mask] 5. loss, metrics = method_obj.compute_loss(self.model, batch, outputs) 6. loss.backward() 7. optimizer.step() 8. optimizer.zero_grad()
为什么最后只有 adapters 会被更新
因为最开始 prepare_model_impl(...) 已经做了:
  for param in model.parameters():
      param.requires_grad = False

然后 optimizer 又只拿了:
  model.mores_adapters.parameters()

所以最后:
  Qwen backbone 不更新
  只有每层 MoReSAdapter 的参数更新
10.1 w_up / w_down / projection 到底是什么
先把 "projection" 这个词忘掉。

当前代码里真正独立的参数只有两组:
  1. linear
  2. w_down

w_up 不是新参数。
w_up 就是:
  w_up = w_down.weight

也就是说:
  current code 里没有第三套独立的 "projection" 参数
  只有一套共享方向矩阵，被上下两个方向共用

如果设:
  D = hidden size
  r = rank
  P = w_down.weight          # shape [r, D]

那么:
  w_down(h) = h @ P^T        # [N,D] -> [N,r]
  w_up(z)   = z @ P          # [N,r] -> [N,D]

所以:
  w_down 和 w_up 不是两套不同矩阵
  它们共用同一个 P

公式:
  h + W_up(Linear(h) - W_down(h))

在当前代码里对应:
  w_down_h = w_down(h)
  linear_h = linear(h)
  update = (linear_h - w_down_h) @ w_up
  h_new = h + update
┌── 先只记一件事：当前代码里只有一套共享方向矩阵 P ───────────────────────────┐ │ │ │ P = w_down.weight │ │ │ │ 现在别管公式，先只看 P 被用了两次： │ │ │ │ 第一次：下投影 │ │ h --用 P^T 做点积--> 一个 rank 空间向量 │ │ 这一步就叫: w_down(h) │ │ │ │ 第二次：上投影 │ │ 一个 rank 空间向量 --再乘 P--> 回到原 hidden space │ │ 这一步就叫: w_up(...) │ │ │ │ 所以: │ │ w_down 和 w_up 不是两套不同参数 │ │ 它们只是“同一个 P 的两种用法” │ │ │ │ 如果你非要把 projection 这个词塞回来： │ │ projection = 这套共享的 P │ └────────────────────────────────────────────────────────────────────────────────┘

10.2 一个最笨的数值例子
假设:
  h = [2.0, -1.0, 0.5, 3.0]
  P = w_down.weight = [0.4, -0.2, 0.1, 0.5]

下投影:
  W_down(h) = h @ P^T
            = 2.0*0.4 + (-1.0)*(-0.2) + 0.5*0.1 + 3.0*0.5
            = 2.55

再假设:
  Linear(h) = 3.10

那么:
  delta = Linear(h) - W_down(h)
        = 3.10 - 2.55
        = 0.55

上投影:
  W_up(delta) = delta @ P
              = 0.55 * [0.4, -0.2, 0.1, 0.5]
              = [0.22, -0.11, 0.055, 0.275]

最后:
  h_new = h + W_up(delta)
        = [2.22, -1.11, 0.555, 3.275]

这个例子里最重要的一句就是:
  上下两个方向都在用同一个 P
把整份讲义压成最短一句：MoReS 训练做的事，是先把原始样本做成带 intervention_mask 的 tokenized sample 和 batch，再在 model(**forward_batch) 时用 pre-hook 读这张 mask、用每层 layer-hook 只改少量 visual token hidden states，最后只更新 adapters。
